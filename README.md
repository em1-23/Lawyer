# منصة المحاماة

دليل إعداد وتشغيل الواجهة والخادم وإدارة دخول لوحة الإدارة. النسخة الإنجليزية في [README.en.md](README.en.md).

## المكونات

- `Lawyer_Frontend`: واجهة React وVite.
- `Lawyer_Backend`: واجهة API بـ Express وقاعدة SQLite.
- مسار لوحة الإدارة: `/control-center/secure-lawyer-conversations-admin-7f3a9c2e8b1d4a6f`.

## إعداد الخادم

1. ثبّت Node.js وnpm.
2. من مجلد المشروع شغّل:

   ```powershell
   cd Lawyer_Backend
   npm install
   Copy-Item .env.example .env
   ```

3. عدّل `Lawyer_Backend/.env`:
   - `ADMIN_ACCOUNTS`: قائمة حسابات بصيغة JSON. الأدوار المدعومة: `master_admin` و`main_admin` و`admin`. استخدم بريدًا مختلفًا لكل حساب.
   - `SMTP_HOST` و`SMTP_PORT` و`SMTP_SECURE` و`SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM`: إعداد SMTP لإرسال أكواد الدخول والتنبيهات. استخدم كلمة مرور تطبيق البريد عند الحاجة، ولا ترفع ملف `.env` إلى Git.
   - `ADMIN_LOGIN_ALERT_EMAIL`: البريد الذي يستقبل تنبيهات الدخول. افتراضيًا يُستخدم بريد أول حساب دوره `master_admin` إذا تُرك الإعداد فارغًا.
   - `FRONTEND_ORIGIN`: أصل الواجهة، مثل `http://localhost:5173` أثناء التطوير.
   - `PORT`: منفذ API، افتراضيًا `5000`.
   - `GROQ_API_KEY`: مطلوب لميزات المساعد التي تستخدم Groq.
4. شغّل الخادم:

   ```powershell
   npm start
   ```

ينشئ الخادم `Lawyer_Backend/data/chat.sqlite` تلقائيًا. يرسل لكل حساب أدمن رمزًا عشوائيًا مستقلًا إلى بريده، ويحفظ بصمة الرمز فقط. صلاحية الرمز 7 أيام؛ يفحص الخادم الصلاحية عند التشغيل وكل دقيقة، ويرسل رمزًا جديدًا عند الحاجة. يستطيع `master_admin` أيضًا تدوير رموز جميع الأدمنز من لوحة الإدارة؛ يُرسل رمز مختلف لكل بريد وتُلغى الرموز والجلسات السابقة للحسابات التي نجح إرسال رمزها.

## إعداد الواجهة

افتح نافذة طرفية ثانية:

```powershell
cd Lawyer_Frontend
npm install
Copy-Item .env.example .env
```

اجعل `VITE_API_URL` في `.env` عنوان الخادم، مثل `http://localhost:5000`، ثم شغّل:

```powershell
npm run dev
```

افتح الرابط الذي يعرضه Vite، ثم أضف إليه مسار لوحة الإدارة المذكور أعلاه. في إعداد التطوير الافتراضي يكون الرابط `http://localhost:5173/control-center/secure-lawyer-conversations-admin-7f3a9c2e8b1d4a6f`.

## الأدوار والتنبيهات

- كل حساب يدخل ببريده ورمزه الخاص؛ الرمز وحده لا يكفي لحساب آخر.
- `master_admin` يستطيع تدوير الرموز ومراجعة حضور الأدمنز. `main_admin` و`master_admin` يستطيعان استخدام إدارة محادثات الاستشارات.
- يرسل الخادم تنبيهًا عند نجاح أو فشل محاولة الدخول إلى `ADMIN_LOGIN_ALERT_EMAIL`. يتضمن التنبيه نتيجة المحاولة، البريد المُدخل، أصل موقع الدخول، عنوان IP الذي رآه الخادم، الجهاز، معلومات المتصفح، طريقة التحقق، ووقت UTC.
- لا يُرسل التنبيه كود الدخول أو كلمة مرور. البريد المُدخل في محاولة فاشلة هو ما كتبه الزائر وليس إثباتًا لهويته. بعد 8 محاولات من عنوان IP والبريد نفسيهما خلال 15 دقيقة، تُرفض المحاولات؛ يُرسل تنبيه واحد عند بلوغ هذا الحد لتقليل الرسائل المتكررة.
- يعتمد إرسال التنبيهات على إعداد SMTP وتسليم مزود البريد. خلف وسيط عكسي أو استضافة سحابية، قد يظهر عنوان الوسيط بدل عنوان الزائر ما لم يُضبط التعامل مع الوكيل الموثوق في الخادم.

## التشغيل في الإنتاج

اضبط `FRONTEND_ORIGIN` و`VITE_API_URL` على نطاقي الواجهة والخادم الفعليين، واستخدم HTTPS، وقيم SMTP صالحة، وحساب `master_admin` تملكه. خزّن الأسرار في إعدادات الاستضافة بدل ملفات المستودع، واحتفظ بنسخة احتياطية من مجلد `Lawyer_Backend/data`.
